Design — Operations & Conversation UX

What the plugin can do, and what the conversations look like

First-time setup

1. User opens VS Code settings → adds "jiraCopilot.baseUrl": "https://jira.mycompany.com"
2. User runs command palette → Jira Copilot: Set Personal Access Token → types PAT → stored in SecretStorage
3. Plugin validates connection on first use and reports clearly if config is missing or the token is invalid

Phase 1 operations (MVP)

Operation Example prompt What happens
Read ticket @jira show me PROJ-123
@jira summarise this ticket		 Fetches and formats: summary, description, status, assignee, priority, reporter, labels
Add comment @jira add comment "Ready for review" on PROJ-123
@jira comment on this ticket that the fix is in PR #42		 Posts the comment via Jira API; confirms with a link back to the ticket
Edit fields @jira set priority to High on PROJ-123
@jira assign this ticket to jane.doe
@jira update the description of PROJ-123		 Updates: summary, description, priority, assignee, labels, fix version. Confirms the change with the new value.
JQL search @jira find all open bugs assigned to me
@jira review sprint tickets against our definition of done		 Runs a JQL query (constructed by the LM or provided literally), returns a summary table of results
Validate ticket @jira check all required fields are set on PROJ-123 Fetches ticket, checks configured required fields (defined in extension settings), reports any missing

Phase 2 (after MVP)

Status transitions — @jira move PROJ-123 to In Review
Fetches available transitions for the ticket first, matches the user's intent to one, then executes. Separate from field edits because Jira exposes a different endpoint (/transitions) and transitions may have required fields (e.g. a resolution).

Ticket detection in practice

Branch: feature/PROJ-123-add-login
→ @jira summarise this ticket → uses PROJ-123 ✓
→ @jira show me PROJ-456 → uses PROJ-456 (explicit override) ✓
→ @jira summarise this ticket on branch main → asks "Which ticket?" ✓
