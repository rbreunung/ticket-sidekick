How should the plugin talk to Copilot?

VS Code offers two distinct ways to extend GitHub Copilot. Understanding this shapes the whole architecture.

A

Chat Participant — @jira

Creates a named agent the user addresses directly in Copilot Chat, e.g. "@jira what is the status of PROJ-123?"

  • User explicitly invokes your plugin with @jira
  • Your code handles the question and writes the reply
  • Clear ownership — user always knows Jira is responding
  • More work to handle free-form natural language yourself
B

Language Model Tools — automatic tool calls

Registers functions (e.g. getJiraTicket, addComment) that Copilot can call automatically when it decides they are relevant — no @ prefix needed.

  • Copilot decides when to use your tools based on context
  • Works in any Copilot Chat conversation, not just when @-mentioned
  • Natural to use — "summarise my open tickets" just works
  • Less control over when and how tools are invoked
C

Both — Chat Participant + Tools

Register tools for ambient use and a dedicated @jira participant for focused conversations.

  • Maximum flexibility for the user
  • More surface area to build and maintain
  • Good long-term target, but heavier for an MVP

My recommendation: B — Language Model Tools.
You said "the plugin shall provide tools to Copilot" — this maps directly to the Tools API. Copilot handles natural language; your plugin handles Jira. Clean split of responsibility, and it's the simpler path for a first version.
