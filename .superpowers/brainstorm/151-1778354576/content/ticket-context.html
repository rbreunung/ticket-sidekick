How does the plugin know which ticket you mean?

When you type @jira summarise this ticket — how does it know which ticket "this" is?

A

Always explicit — user provides the ticket ID

"@jira look up PROJ-123" — you always name the ticket.

  • Simple to implement, no guessing
  • Unambiguous — exactly what you asked for
  • Slightly more typing, but clear and predictable
B

Auto-detect from context

Plugin inspects the current git branch name (e.g. feature/PROJ-123-login) and uses that ticket automatically when none is specified.

  • Much smoother — just say "this ticket" and it knows
  • Works when your team names branches with ticket IDs (very common)
  • Falls back to asking if no ticket ID is found in the branch name
  • Small extra logic to extract ticket ID from branch
C

Auto-detect with explicit override

Detects from branch by default; user can always say a specific ticket ID to override.

  • Best of both: low friction for the common case, precise when needed
  • "@jira summarise this ticket" → uses branch ticket
  • "@jira look up PROJ-456" → uses PROJ-456 regardless of branch
  • Minimal extra complexity over B

My recommendation: C.
Branch-based auto-detection is one of those small things that makes a tool feel intelligent. Most teams use ticket IDs in branch names (feature/PROJ-123-...), so this works reliably in practice. The logic is just a regex on the branch name — very low cost, very high UX payoff.
